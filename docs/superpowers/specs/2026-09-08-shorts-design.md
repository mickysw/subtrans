# subtrans / shorts — 롱폼에서 하이라이트를 찾아 쇼츠로 편집하는 기능

> 이 문서는 설계(spec)다. 승인되면 `subtrans/docs/superpowers/specs/2026-09-08-shorts-design.md`로
> 옮겨 커밋하고, **모델을 Opus로 바꿔** 구현 계획과 구현을 진행한다.

## 1. 목적

`subtrans`로 만든 롱폼(자막 입힌 인터뷰 영상)에서 **시청자가 가장 궁금해할 구간 여러 개를 찾아
유튜브 쇼츠로 자동 편집**한다. 기존 오픈소스(OpenShorts, AutoClip 등)와의 차이는 **편집**이다.
그것들은 구간을 골라 그대로 자르지만, 이 도구는

- **후킹 문장을 맨 앞으로** 당겨 첫 1~2초에 귀가 트이게 하고
- **말 사이의 빈 공간과 군말**을 걷어내 루즈함을 없앤다

얼굴 추적(말하는 사람을 크게)은 **있으면 좋은 것**이지 필수가 아니다. 정확도가 기준을 넘을 때만 켠다.

## 2. 확정된 요구사항 (인터뷰 결과)

| 항목 | 결정 |
|---|---|
| 입력 | **항상 subtrans 롱폼 작업 결과**(`work/<id>/`)에서 출발. 별도 다운로드·받아쓰기 없음 |
| 편집 깊이 | 순서를 바꿔 후킹을 앞으로. 단 **한 후보 구간(30~90초) 안에서만** 재배치 |
| 무음 | 말 사이 빈 공간 제거. 군말(um, uh) 제거 |
| 세로 화면 | 1차: 정적 크롭. 2차: 말하는 사람 따라가기 — **정확도 게이트 통과 시에만** |
| 검수 | 후보를 먼저 보여주고, **고른 것만** 굽는다 |
| 길이 | 쇼츠 하나 30~60초 |
| 개수 | 영상 길이에 비례. **6분당 1개, 최소 2 · 최대 6** (26분 → 4개) |
| 자막 | 한국어. 1차 문장 단위(크게, 2줄). 2차 말하는 어절만 색 강조 |
| 출처 | 영상에 굽지 않고 **유튜브 설명란용 텍스트 파일**로 함께 생성 |
| 비용 | LLM은 Gemini 무료 등급(기존 `translate.py` 경로 재사용). 추가 비용 0 |

## 3. 전체 흐름

```
work/<id>/                         ← subtrans 롱폼 결과 (이미 있음)
  words.json  cues.json  ko.srt  en.srt  video.mkv  fetch.json
        │
        ▼
 ① candidates   LLM이 후보 구간 N개 선정 ─────────────▶ shorts/candidates.json
        │
        ▼
 ② edl          후보마다 편집 결정 목록 생성
                 (후킹 앞으로 · 무음 제거 · 군말 제거) ──▶ shorts/edl_<n>.json
        │
        ▼
 ③ review       후보 목록 화면. 제목·후킹·길이·재배치된 대본. 고르기
        │
        ▼  (고른 것만)
 ④ render       ffmpeg 2단계 (아래 §6)
        │        └ 2차: framing(얼굴 추적) — 게이트 통과 시에만 개입
        ▼
 shorts/<n>_<제목>.mp4   1080x1920
 shorts/<n>_<제목>.txt   유튜브 제목·설명·출처·해시태그
```

각 단계는 파일을 남기고 다음 단계는 파일만 읽는다(기존 subtrans와 같은 원칙). 어디서든 재개 가능.

## 4. 단계별 설계

### ① 후보 선정 — `shorts/candidates.py`

**입력**: `cues.json`(문장 단위 조각, 시각 포함) + `fetch.json`(제목·채널).
**LLM 호출 1회.** 영어 대본 전체를 시각과 함께 주고 아래를 JSON으로 받는다.

```json
[{ "start_cue": 118, "end_cue": 141,
   "title": "손흥민이 MLS를 거절했던 이유",
   "hook_cue": 131,
   "why": "예상과 반대되는 결정 + 구체적 이유",
   "score": 0.92 }]
```

- 요청 개수 = 목표의 2배. 받은 뒤 `score`순으로 목표 개수만 남긴다. 목표 = `clamp(길이분/6, 2, 6)`
- 프롬프트 기준: **질문이 생기거나 예상을 뒤집는 순간**, 숫자·이름 같은 구체성, 한 호흡으로 끝나는 이야기. 인사·잡담·광고 제외
- **검증(코드)**: cue 번호가 실제 범위 안인지, 구간 30~90초인지, 후보끼리 50% 이상 겹치지 않는지. 위반은 버린다
- 왜 cue 단위인가: cue는 이미 문장 경계에서 끊겨 있고(`segment.py`가 보장), `ko.srt`와 **번호가 1:1**이라
  한국어 자막을 다시 번역하지 않고 그대로 쓸 수 있다

### ② 편집 결정 목록 — `shorts/edl.py` ★핵심

후보 하나를 받아 **"원본의 어느 시각 조각을 어떤 순서로 이어 붙이는가"**를 만든다.

**2-a. 후킹 재배치** — LLM 호출 1회(후보당)
후보 구간의 cue 목록을 주고 "맨 앞에 둘 cue 번호 하나(또는 연속 2개)"를 받는다.
규칙은 코드로 강제한다 — LLM에게 순서 전체를 맡기지 않는다.

```
출력 순서 = [hook cues] + [나머지 cues, 원래 순서 그대로]
```

검증: 모든 cue가 정확히 한 번씩. hook은 후보 안의 cue여야 함. 실패 시 재배치 없이 원래 순서 사용(포기하지 않고 강등).

**2-b. 무음 제거** — 코드만, LLM 없음
`words.json`의 단어 시각으로 계산한다.

- 연속 단어 사이 간격 > **0.35초** → **0.15초**로 줄임 (자연스러운 숨은 남김)
- cue 경계(문장 사이) > 0.6초 → 0.25초
- 재배치로 붙은 이음새(hook 끝 → 원래 첫 문장) → 0.30초
- **단어 안쪽은 절대 자르지 않는다**

**2-c. 군말 제거** — 코드만
`words.json`에서 `um, uh, uhm, hmm, erm` 단독 단어를 제거하고 그 시간을 무음으로 취급해 2-b 규칙 적용.
`like`, `you know`는 **제거하지 않는다**(문장 성분일 수 있어 위험).

**2-d. 길이 맞추기**
편집 후 길이가 60초 초과면 **끝 문장부터** 뺀다(hook은 절대 안 뺌). 25초 미만이면 후보 폐기.

**출력** `edl_<n>.json`:
```json
{ "spans": [{"src_start": 731.20, "src_end": 734.85, "cue": 131}, ...],
  "words_out": [{"w":"never","out_s":0.00,"out_e":0.31,"cue":131}, ...],
  "cues_out": [131, 118, 119, ...],
  "duration": 47.3,
  "removed_silence_s": 6.8 }
```

`words_out`은 **출력 타임라인 기준** 단어 시각 — 2차 어절 강조 자막의 재료다.

**검증**: 전체 span 합 = duration ±0.05초, span마다 ≥ 0.4초, 제거된 무음이 원래 길이의 40% 초과면 경고(뭔가 잘못됨).

### ③ 검수 화면 — `shorts/review.html` (생성물)

기존 `review.html`과 같은 방식: 서버 없는 HTML 한 장.

- 후보 카드: 제목 · 길이 · 후킹 문장(굵게) · **재배치된 순서의 한국어 대본** · 원본 시각
- 카드 시각을 누르면 롱폼 `preview.mp4`가 그 지점으로 점프 (이미 있는 것 재사용)
- 체크박스로 고르고 **[선택 저장]** → `shorts/selected.json` 내려받기 → 폴더에 넣으면 ④ 진행
- 대시보드(별도 계획 B)가 생기면 그 안으로 흡수. 지금은 독립 동작

### ④ 렌더 — `shorts/render.py`

**두 단계 ffmpeg.** 한 번에 하면 재배치·크롭·자막 시각이 서로 얽혀 디버깅이 불가능하다.

**4-a. 이어 붙이기** → `clip_<n>_raw.mp4`
spans를 `trim`+`concat`(영상·음성 함께). **거의 무손실**(crf 10)로 저장 — 60초라 용량 부담 없음.
이 파일의 타임라인 = 최종 타임라인. 이후 모든 시각 계산이 단순해진다.

**4-b. 세로 변환 + 자막 + 인코딩** → `<n>_<제목>.mp4`
- 크롭 → `scale=1080:1920` → ASS 자막 → h264 crf 17, AAC 복사 (기존 `burn.py` 설정 재사용)
- **1차 크롭 = 정적.** MediaPipe로 클립 전체에서 **가장 큰 얼굴의 평균 위치**를 한 번 구해 그 중심으로 9:16을 자른다.
  얼굴이 없으면 화면 중앙. 움직이지 않으므로 떨림·오판이 없다. 시청에 충분하다(사용자 확인)
- 2차 = §5의 동적 추적. **게이트 통과 시에만 4-b의 크롭 입력을 바꾼다.** 나머지는 동일

**자막 스타일** (`style.json`에 `shorts` 섹션 추가)
- 한국어, 문장 단위, `ko.srt`에서 cue 번호로 가져옴 → **재번역 없음**
- 크게(캔버스 1080 기준 72px), 최대 2줄, 화면 세로 65~75% 지점, 흰 글씨 + 굵은 검정 테두리
- 2차: `words_out` 시각을 한국어 어절에 **비례 배분**해 ASS 가라오케(`\k`)로 말하는 어절만 색 변경.
  영어 단어 시각 → 한국어 어절은 근사라는 점을 문서에 명시. 통통 튀는 애니메이션은 넣지 않는다

**설명란 파일** `<n>_<제목>.txt`
```
[제목] 손흥민이 MLS를 거절했던 이유
[설명]
(후킹 문장 한국어)

원본: The Late Run — https://www.youtube.com/watch?v=...
전체 인터뷰 한국어 자막본: (사용자 채널 롱폼 링크 자리)
#손흥민 #인터뷰 ...
```
채널명·URL은 `fetch.json`에서. 롱폼 링크 자리는 비워두고 사용자가 채운다.

## 5. 2차 — 말하는 사람 따라가기 (`shorts/framing.py`)

**원리**: 우리는 **언제 말이 나오는지**를 단어 단위로 안다. 그 시간에 **어느 얼굴의 입이 움직이는지**만 맞추면 된다.

1. `clip_<n>_raw.mp4`를 **초당 5프레임**만 뽑아 MediaPipe로 얼굴 위치 + 입 벌림 정도를 잰다 (CPU로 충분)
2. 얼굴들을 위치로 묶어 사람 A/B로 나눈다
3. 문장(cue)마다: 그 시간 동안 입 움직임 분산이 큰 얼굴 = 화자
4. 화자 바뀔 때만 크롭 중심 이동. **최소 1.0초 유지**(깜빡임 방지), 이동은 0.3초에 걸쳐 부드럽게
5. ffmpeg `sendcmd`로 프레임 시각별 크롭 x좌표를 넘긴다 (타임라인이 raw 클립 기준이라 단순)

**정확도 게이트** — 이걸 통과 못 하면 **1차 정적 크롭으로 자동 강등**하고 이유를 남긴다.

- 말하는 구간의 **85% 이상**에서 "입 움직이는 얼굴이 정확히 하나"로 판별돼야 함
- 얼굴이 하나만 검출되는 클립은 게이트 불필요 (그 얼굴 추적)
- 게이트 결과와 판별률을 `edl_<n>.json`에 기록 → 나중에 기준을 조정할 근거

**사용자의 입장**: 얼굴 추적이 틀리면 안 하느니만 못하다. 그래서 강등이 기본 동작이다.

## 6. 품질 게이트 (subtrans의 원칙 그대로 — 사람이 보기 전에 기계가 거른다)

| 지점 | 검사 | 실패 시 |
|---|---|---|
| ① 후보 | cue 범위·길이·겹침 | 해당 후보 버림 |
| ② EDL | cue 한 번씩·span ≥0.4초·합계 일치·무음 제거율 <40% | 재배치 강등 또는 후보 버림 |
| ④-a | raw 길이 = EDL duration ±0.2초, 오디오 스트림 존재 | 중단, 원인 출력 |
| ④-b | 출력 1080x1920, 길이 유지, 자막 트랙 굽힘 확인 | 중단 |
| ⑤ 추적 | 판별률 ≥85% | 정적 크롭 강등 |

## 7. 파일 구조

```
subtrans/
  shorts/
    candidates.py   edl.py   render.py   framing.py(2차)   review_page.py
  prompts/
    shorts_candidates.md   shorts_hook.md
  style.json           ← "shorts" 섹션 추가
  run.py               ← `--shorts` 옵션 (①②③), `--shorts-render` (④)
work/<id>/shorts/
  candidates.json  edl_1.json ...  review.html  selected.json
  clip_1_raw.mp4  1_<제목>.mp4  1_<제목>.txt ...
```

**재사용하는 기존 코드**: `steps/translate.py`의 `Translator`(Gemini 호출·JSON 파싱·재시도),
`steps/srtlib.py`, `steps/burn.py`의 `build_ass()`·인코딩 설정·`safe_filename()`, `steps/review.py`의 HTML 뼈대.

## 8. 구현 순서 (Opus)

1. **①②만 먼저** — 26분 영상으로 `candidates.json`·`edl_*.json`을 만들고 **대본을 눈으로 읽어** 후킹 재배치가 말이 되는지 확인. 렌더 전에 판단 품질을 본다
2. ③ 검수 화면
3. ④ 렌더, 정적 크롭 — **여기까지가 1차.** 쇼츠 1개를 끝까지 만들어 재생·길이·자막 확인
4. 2차: 어절 강조 자막 → 동적 추적 + 게이트. 각각 **켜기 전/후를 같은 클립으로 비교**해 나아졌을 때만 기본값으로

## 9. 검증

- 26분 영상 → 후보 4개 → 전부 EDL 생성 → 2개 골라 렌더
- 렌더 결과: `ffprobe`로 1080x1920·길이·오디오 확인. 실제 재생해 이음새(hook→본문)가 어색하지 않은지 듣기
- 무음 제거 전후 길이와 제거율 출력. 40% 넘는 클립이 있으면 규칙 재검토
- 2차 추적: 게이트 통과율과 실제로 맞게 잡았는지 3개 지점 스크린샷으로 대조

## 10. 안 하는 것

- 영상 전체에서 문장을 끌어와 조합하기 (맥락 왜곡 위험 — 한 구간 안에서만)
- `like`/`you know` 자동 제거 (문장 성분일 수 있음)
- 통통 튀는 자막 애니메이션 (AI 티)
- 자동 업로드 (검수 후 사람이 올린다 — 기존 원칙)
- 얼굴 추적을 게이트 없이 강제 적용
